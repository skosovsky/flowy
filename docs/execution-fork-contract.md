# Historical inspection and execution fork contract

## Address, capabilities and ownership

History is optional: ordinary Start/Resume require only ExecutionStore. ExecutionHistoryStore adds exact nonzero revision loading; no absent/pruned revision may fall back to latest. Inspection receives the exact source execution/revision and expected envelope digest. It returns detached sealed raw data without domain codecs, leases, migrations, nodes or external actions. Host controls authorization and retention. Unsupported history, unavailable checkpoint, source digest mismatch and corrupt source are distinct errors; infrastructure errors are not disguised as absence.

Fork creates a new execution identity and immutable lineage to that exact inspected source. Source head/history/lease remain untouched. A new target is committed under its own lease and revision-zero OCC; an existing target rejects rather than overwriting. Successful creation is a saved boundary, not implicit node execution. Failure acknowledges no target checkpoint; an acquired target fence/head may remain as normal storage metadata, never a runnable partial execution.

## Transformation, projection and activity modes

A pure named transform receives detached source progress and the explicit source descriptor. It produces target state/cursor under the target runner descriptor; compatibility is checked before target decoding. Fork transform and opaque-state sanitation are separate named contracts. Runtime clears child cursors, activity bindings, source effects, journal, waits, children, terminal and runtime counters rather than transferring operational handles. Materialized source results can be retained only inside host-transformed state; they never authorize new effects or imply rollback.

Default mode is fake, not live. Fake fork execution requires a host-supplied named fake activity boundary and may never invoke the activity's live dispatcher. Nodes are subject to the same graph-wide pure/replay-safe declaration: arbitrary host I/O outside activities cannot be intercepted. Missing fake activity capability rejects before node execution; child graphs additionally require a fake child dispatcher before any child intent/launch, with no live fallback. Live mode requires explicit persisted policy and a matching host authorization gate on every recovery, plus a separately named mandatory pure projection of opaque state before target creation. Core cannot detect embedded approvals/reservations and cannot assert that a host projection actually removed them; host owns that contract. Missing projection or gate rejects before callbacks/nodes, never silently downgrades live into fake. Caller-owned projection registration is copied at Fork entry: a host callback cannot change the already validated label/callback pair through an aliased registration pointer.

Unknown/running/prepared external activities, armed waits and unsettled or unjoined descendants block fork until explicit source resolution; no blind redistribution of pending work. New activity intents use the new execution identity and fresh activation, so sibling forks cannot journal-hit source or each other. Lease expiration does not resolve an unknown source action.

## Commit protocol and failures

Inspect and validate source address/seal/descriptor/collections/lineage before transform. Check mode, labels, projection requirements and source unresolved work before acquiring target. Acquire target with heartbeat, reject an existing target, perform pure transformation/projection on detached bytes and validate target pointer/state with target codecs. Recheck cancellation/lease before one fenced initial commit containing fresh progress and lineage. No source write is performed. Persisted mode/policy/projection/transform/source labels must survive restart and be checked before host execution; lineage changes through migrations are forbidden.

Typed errors distinguish unsupported history, unavailable exact checkpoint, incompatible descriptor/state, failed transform/projection, missing activity policy, unresolved source descendants, target conflict and source digest mismatch. No fallback to latest, no inherited approval and no implicit source migration.

## Required conformance

Every raw store commit must enforce immutable creation lineage under the same lock/transaction as OCC and fencing. Initial creation accepts only well-formed lineage addressed to the target. Later commits compare with the committed predecessor and reject removal, addition to an ordinary execution, or any change, including fake/live mode, source digest, labels and creation time, with ErrExecutionCorrupt. A valid lease does not authorize rewriting provenance; rejection must leave head/history unchanged. The predecessor comparison is a storage-write invariant, not authentication against an administrator rewriting database records directly. Independent recovery protection against resealed storage corruption requires separate acceptance evidence.

Native stores additionally retain an independent creation-lineage anchor beside the execution head. The anchor is established atomically by the initial commit, never by lease acquisition, and is not overwritten by later commits, migrations, lease release or history retention. Latest/exact loads, discovery and later commits compare envelope lineage with this anchor before exposing executable raw data; a recomputed envelope seal does not excuse a mismatch. Ordinary executions have a nil anchor and cannot later acquire lineage. No history capability is added to the base runtime API. Existing fork heads without an anchor must undergo explicit host-controlled data migration or be rejected; recovery must not infer an anchor from untrusted current payload. This detects isolated payload/anchor corruption, not coordinated rewrites of both storage records by a database administrator; authentication and database permissions remain host responsibilities.

Exact historical inspection versus later latest; detached mutation; unsupported store; absent/pruned revision; mismatched address/digest; zero node/codec/lease calls during inspection. Historical correction into new lineage without source changes; default fake dispatch cannot call live code; explicit live projection/gates; two target operation identities; unresolved descendants, target conflict and transform/commit faults with no acknowledged partial target. Repeat on PostgreSQL with original pools closed before recovery. An already-created target retains authority through its independent creation anchor even after source history or target creation payload is pruned. Exact source inspection and creating another fork from that source still require the addressed source payload; its absence returns ErrExecutionCheckpointUnavailable. Retention does not replace the source with latest or invalidate a retained target anchor.

## Implementation and evidence

DurableRunner.Fork now creates a fresh target boundary and returns its token without node calls. ForkLineage persists exact source reference/descriptor, creation target descriptor/identity, fake/live mode, policy/transform/projection labels and UTC creation time. Source effects/journal/children/waits/terminal/runtime handles and counters are not copied. Only target lease/history are written. Resume/ResumeStream require a compatible current policy before state decoding or migration. Default fake creation with no executable policy remains inspectable but cannot be resumed. Fake activity dispatch replaces live dispatcher/reconcile/classifier callbacks; completed outcomes carry ActivitySimulated, not ActivityLive. Fake child launch requires a separate fake child dispatcher; cancellation notification is local-only. Live creation requires explicit mode/label, a separately named projection and current authorization, which is checked again on recovery.

Core fake/two-target-identity, live projection/revoked-authorization, initial commit fault, active-target conflict and per-dispatch authorization fixtures have passed ten race repetitions. Unresolved activity/child/wait source refusal, transform/projection/codec failures, fake child join/cancel/no-fallback, sync/stream migration retaining immutable lineage/mode, wrong-mode refusal before migration, and adversarial projection-registration substitution have also passed ten repetitions. The PostgreSQL three-pool historical correction fixture passed ten repetitions, including fake ResumeStream, cached completion, immutable lineage/source and simulated provenance.

TestForkCompletedSourceOutcomesAndHandlesNeverTransfer verifies completed source journal/effects/runtime handle reset and new fake identities without live dispatch. TestMemoryForkAnchorRejectsResealedHistory and TestForkPersistentRecoveryRejectsResealedLineage verify independent-anchor checks after resealing payloads. TestForkPersistentLineageCannotBeRewrittenUnderValidFence verifies storage-write refusal with unchanged history even under a valid owner. Exact source-history absence remains unavailable, never a latest fallback. Coordinated administrative rewriting of both anchor and payload is not an authentication guarantee. Per-fixture backend/recovery coverage and current final-audit status are recorded in task22-progress.md and the requirement registry; this document alone does not establish complete delivery or release readiness.
